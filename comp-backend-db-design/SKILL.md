# 数据库设计

## 核心原则

**先设计表结构，再写数据访问层。**

表结构决定了业务逻辑的上限。表没设计好，后面怎么封装都别扭。

## 输出格式

```markdown
### 表名 {table_name}
- 字段：{name} {type} {约束}
- 主键：{字段}
- 索引：{字段 + 索引类型}
- 外键：{目标表} ({字段})
- 备注：{用途说明}
```

## The Gate Function

```
1. 确定实体和关系（1:1, 1:N, N:M）
2. 设计字段（类型 + 长度 + 约束 + 默认值）
3. 定主键和索引（高频查询字段要建索引）
4. 定外键关系
5. 写迁移脚本（优先用 ORM 迁移）
```

## 规则

- 优先 ORM 迁移，不手写 SQL
- 索引覆盖高频查询场景，但不过度索引
- 关系显式标注，不藏在外键里等人猜

## Rationalization Prevention

| 想说的话 | 真相 |
|---------|------|
| 「先写个通用字段表，后面再加字段」 | 后面加的字段往往没有索引、没有约束 |
| 「不用迁移，手动改一下数据库就行」 | 谁改的？什么时候改的？→ 不知道 |
| 「这个关系等用到再补」 | 漏了关系 = 漏了外键约束 = 数据不一致 |
