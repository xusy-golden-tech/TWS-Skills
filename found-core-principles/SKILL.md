# TWS 全局规则详细说明

> 本文件是 `using-tws` 中 4 条全局规则的详细版本。
> 主 agent 不预加载。按需读取。

---

## 1. Design First（先设计再动手）

没有设计书就不写代码。设计书是后续所有工作的唯一依据。

跳过设计书 ≈ 蒙着眼睛写代码。写设计书的 10 分钟，省的是后面几个小时的返工。

## 2. Incremental Implementation（增量实施）

把设计拆成可独立验证的任务，逐个执行。每个任务必须有明确的完成标准和验证方式。

**禁止：**
- 「这个不用测了吧」→ 必须测
- 「跳过这一步」→ 没有跳过
- 「跟之前一样」→ 重新验证

## 3. Verify（验证）

测试通过只是最低要求。还要检查：边界条件、设计书同步、没有遗留的 TODO/FIXME。

**通过条件（全部满足）：**
- 测试通过（或开发者明确确认跳过）
- 设计书已同步
- 边界条件已覆盖
- 没有遗留的 TODO/FIXME

## 4. Design Sync（改了代码就必须同步设计书）

不改设计书 = 代码没改完。这是全局规则，不限流程。

| 改了什么 | 设计书要同步 |
|---------|------------|
| 功能逻辑 | 更新功能描述 |
| 接口签名 | 更新接口定义 |
| 参数 / 返回值 | 更新参数说明 |
| 新增模块 | 新建设计书 |
| 删除功能 | 标记废弃，说明原因 |

设计书同步是执行的一部分，不是可选的后续步骤。

同步方式详见 `comp-design-sync/SKILL.md`。
