## P50: Performance 5.0 — 突破 Python 瓶颈

**问题**：g-ass-source 289s vs CBM 14.1s（20x）。v5.2.0-v5.7.0 的四轮优化已耗尽 SQLite 层和提取器层的低挂果实。剩余瓶颈在 tree-sitter 解析和 Python 解释器开销。

**目标**：289s → ≤ 60s（5x 提升）

### P50a: Tree-sitter Query 替代手工 AST Walk（预估 -40%）

当前 extractor 使用 `node.walk()` + Python `for` 循环遍历 AST，这是最大热点。

用 tree-sitter Query API（C 层）替代 Python AST walk。Query 表达式直接匹配目标节点模式：`(function_definition name: (identifier) @name)`。Python extractor 重写为 Query-first，只在需要复杂逻辑时 fallback 到 walk。

### P50b: Process Pool 常驻 + 预热（预估 -15%）

- 常驻 worker pool：索引完成后不销毁，等待下次任务
- 预加载 Language 和 Query 对象到每个 worker（一次编译，永久缓存）
- `tws-graph serve` 模式下 pool 持续存活

### P50c: SQLite 写入管道化（预估 -10%）

- 写入线程池：worker 只管提取，结果放入无锁队列
- 专用写入线程从队列取结果 → 批量 INSERT
- 解耦提取和写入（提取不等待 I/O）

### P50d: 增量缓存层（预估 -5%）

- 基于 content_hash 的解析结果缓存
- 未变文件直接从缓存加载（跳过 parse + walk + extract）

## P51: Extractor 深度升级 — Go/Rust/C++/C#/PHP

**目标**：五个 extractor 达到 Python extractor 同等深度。

### P51a: Go
1. 包与导入系统 → imports 边
2. 接口实现检测 → implements 边
3. 结构体方法 → 接收者类型绑定
4. struct tag 解析 → decorates 等价边
5. 变量读写追踪

### P51b: Rust
1. 模块系统 → imports 边
2. Trait 实现 → implements 边
3. 宏调用 → calls 边
4. 生命周期 + 泛型 → type_ref 边
5. 属性 `#[derive]` → decorates 等价边

### P51c: C++
1. include 追踪 → imports 边
2. 虚函数覆写 → overrides 边
3. 模板 → type_ref 边
4. 命名空间 → qualified_name 格式化
5. 构造函数 → instantiates 边

### P51d: C#
1. using 指令 → imports 边
2. 属性 `[JsonProperty]` → decorates 边
3. 泛型 → type_ref 边
4. LINQ 链式调用 → 链式 calls
5. 属性访问器 → reads/writes 边

### P51e: PHP
1. use 导入 → imports 边
2. Trait → implements 等价边
3. 注解 → decorates 边
4. 类型提示 → type_ref 边
5. 命名空间 → qualified_name 格式
