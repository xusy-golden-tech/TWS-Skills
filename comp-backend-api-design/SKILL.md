# 后端 API 设计

## 核心原则

**先定义接口，再写实现。**

接口是前后端之间的契约。接口定义好了，两端可以并行开发。

## 输出格式

```markdown
### {Method} {path}
- 功能：{一句话描述}
- 请求体：{字段: 类型, 必选/可选}
- 响应 200：{成功时的格式}
- 错误响应：{错误码 + 含义}
- 鉴权：{是否需要 token / 权限}
```

## The Gate Function

```
1. 确定路由和 HTTP 方法
2. 定义请求体（所有字段 + 类型 + 约束）
3. 定义正常响应（200）
4. 定义错误响应（至少 400/401/500）
5. 确定鉴权方式
```

## 规则

- RESTful 风格
- 错误码统一（400=参数错, 401=未登录, 403=无权限, 404=不存在, 500=服务端）
- 鉴权统一走中间件，不在每个路由实现

## Rationalization Prevention

| 想说的话 | 真相 |
|---------|------|
| 「接口很简单，边写边定」 | 边写边定 = 前后端各定各的，联调时对不上 |
| 「错误码后面再加」 | 后面忘了加，上线了用户看到 500 不知道什么意思 |
