# 编写文档

## 流程

```
① 内容审计 → ② 结构设计 → ③ 撰写 → ④ 审校 → ⑤ 发布
```

## ① 内容审计

```
1. 现有文档有哪些？缺什么？
2. 目标读者是谁？
3. 输出：文档清单 + 缺失项
```

## ② 结构设计

```
1. 目录结构
2. 每章写什么
3. 确认
```

## ③ 撰写

```
1. 按章节顺序写
2. 代码示例可运行
3. 每写完一章标记完成
```

## ④ 审校

```
1. 读一遍：通顺吗？
2. 验证：代码示例能跑吗？
3. 检查：有没有遗漏？
```

## ④-2 同步（如涉及设计书）

```
如果文档变更涉及 API/接口/架构描述的修改，调用 design-sync 同步设计书。
不涉及设计书的文档变更跳过此步。
```

## ⑤ 发布

```
1. 确认格式正确
2. 更新文档索引
```
