# 根因分析

## 核心原则

**找到源头，而不是找到出现症状的地方。**

## The Gate Function

```
1. 追踪：从错误表象往回追溯（调用链、数据流）
2. 定位：找到第一个出错的位置（文件:行号）
3. 分析：为什么会出错（逻辑错？数据错？外部依赖错？）
4. 评估：影响范围（哪些功能、哪些用户、什么条件触发）
5. 输出：根因 + 影响
```

## 时间盒

```
如果在定位阶段迭代超过 3 次仍未确认根因：
→ STOP
→ 整理所有假设和证据
→ 输出排查报告（已排除什么、还剩什么可能性）
→ 提交给开发者判断方向

限制：最多 3 次假设验证循环
超过 → 上报，不是继续猜。
```

## Output Format

```
- 根因：{文件:行号} {具体原因}
- 触发条件：{什么场景下出现}
- 影响：{哪些功能/用户}
- 建议修复：{修改方向}
```

## Rationalization Prevention

| 想说的话 | 真相 |
|---------|------|
| 「这个问题我见过」 | 看过类似的 ≠ 就是同一个原因。追踪确认再下结论 |
| 「肯定是 XX 的问题」 | 「肯定」= 还没查。查完再说话 |
| 「先改这里试试」 | 试 = 没定位到根因。定位清楚了再改 |
