# 修复 Bug

> **与热修复（hotfix）的区分：**
> - `fix-bug` 走完整质量流程（方案确认→回归→防复燃），适用于**日常开发/非紧急** Bug
> - `hotfix` 跳过方案确认和集成测试，适用于**生产环境紧急**问题
> - 入口 skill 自动判断：用户说「紧急」「hotfix」→ 走 hotfix；否则走 fix-bug
> - 如果走 fix-bug 简化路径后发现时间仍然不够 → 建议用户考虑改走 hotfix

## 复杂度门禁（第 0 步）

```
检查条件：
□ 只改一行或一个表达式？
□ 不改模块结构、不改接口？

全部满足 → 简化路径
任一不满足 → 完整路径
```

### 简化路径（小修复）

```
根因 → 修复 → 验证 → 同步
跳过：方案确认、回归、防复燃、集成测试
```

### 完整路径

```
复现 → 根因 → 方案 → 修复 → 回归 → 防复燃 → 影响评估 → 集成 → 同步
```

## 完整路径

### ① 复现

子 agent 通过 Skill 工具加载 `comp-reproduce`

```
1. 确认 Bug 现象
2. 找到复现步骤
3. 验证重现 → 记录
```

### ② 根因分析

子 agent 通过 Skill 工具加载 `comp-root-cause-analysis`

```
定位到具体位置 → 分析原因 → 评估影响
```

### ③ 修复方案

```
1. 怎么修？改哪里？
2. 有没有副作用？
3. 确认后再动手
```

### ④ 修复

子 agent 通过 Skill 工具加载 `comp-implementation`（最小改动模式）

```
1. 实施修复
2. 验证 Bug 不再复现
```

### ⑤ 单元+回归

```
链式验证 → 检查修复已完成

1. 跑相关测试
2. 检查连锁影响
```

### ⑥ 代码审查

独立子 agent 通过 Skill 工具加载 `comp-code-review`

```
派独立子 agent 审查修复代码：
□ 修复逻辑是否正确？有没有遗漏的边界情况？
□ 有没有引入新问题？
□ 测试是否覆盖了修复点？
□ 符合代码规约吗？
```

### ⑦ 防复燃（原⑥）

```
这个 Bug 是孤例还是某类问题？
同类问题可能在哪出现？
要加什么防护？
```

### ⑧ 影响评估（原⑦）

子 agent 通过 Skill 工具加载 `comp-impact-assessment`

```
如果修复涉及跨模块影响，评估连锁范围。
```

### ⑨ 集成测试（原⑧）

```
链式验证 → 检查所有任务完成

跨模块连锁影响检查。
```

### ⑩ 同步（原⑨）

子 agent 通过 Skill 工具加载 `comp-design-sync`

## 简化路径（小修复）

```
1. 根因 → 找到位置
2. 修复 → 改代码
3. 验证 → Bug 不再复现 + 跑核心测试
4. 同步 → 设计书同步

简化跳过了：方案确认、完整回归、防复燃、集成测试。
但「验证」不能跳——必须确认 Bug 不再出现。
```
