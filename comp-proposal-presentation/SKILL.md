# 展示材料

## 核心原则

**展示材料是方案的说服力翻译，不是方案文档的复读。**

客户听你讲方案时不会逐行读方案文档。他们关心三件事：你懂我的问题吗？你的解法靠谱吗？为什么是你？

## 前置输入

- 方案文档（已锁定）
- 报价方案（已锁定）

## 子能力

### A. 受众分析

在动笔前，先判断你讲给谁听：

```
决策者（拍板的）：
  关心 — 投入产出比、风险、时间线、对业务的影响
  不关心 — 技术细节、用什么框架
  → 多讲价值和风险可控，少讲技术实现

技术评估者（把关的）：
  关心 — 架构合理性、技术选型、可维护性、扩展性
  不关心 — "我们有类似案例"（除非是同类技术栈）
  → 架构图和选型理由要扎实，他们会在意

日常使用者（最终用的）：
  关心 — 操作是否方便、能解决什么痛点、长什么样
  不关心 — 用什么数据库、几个模块
  → 多展示界面/Beta 原型/操作流程

如果观众混合（通常如此）：
  → 按"决策者逻辑"讲主线索，在方案详情页给技术评估者留信息，在 Demo 环节给使用者感受
```

**为什么先分析受众：** 同样的方案，讲给 CFO 和讲给 CTO 是两套材料。不做受众分析 = 对着所有人讲一样的话 = 每个人都没被说服。

### B. PPT 大纲

#### 叙事结构（标准 13 页版）

```
第 1 页 — 封面
  标题：{方案核心价值，不是"XX 项目方案"}
  示例："帮 XX 公司搭建统一的客户数据平台" 而非 "XX 公司 CRM 系统建设方案"
  副标题：{项目名称 + 日期}

第 2-3 页 — 问题
  第 2 页：客户当前的状况和痛点（用客户的语言，让他们觉得"你懂我"）
  第 3 页：不解决的后果（量化如果能——"每年损失 X 万""每个客服每天浪费 Y 小时"）
  规则：问题必须是客户亲口说过或材料中体现的，不能是你臆想的痛点

第 4-5 页 — 方案
  第 4 页：一句话说清我们做什么 + 为什么这样做
  第 5 页：简化版架构图（能一眼看懂，不超 5 个方框）

第 6-7 页 — 方案亮点
  选 2-3 个方案中最有差异化的设计决策，展开讲：
  - 为什么选这个做法？
  - 和常规做法比好在哪里？
  - 对客户来说意味着什么？（快？省？稳？）
  不要罗列所有模块——列所有 = 没有重点

第 8 页 — 交付计划
  里程碑时间线（一页可视化，不超 4 个阶段）
  每个阶段：{时间} → {交付什么} → {客户能验证什么}

第 9 页 — 风险透明
  选 2-3 个关键风险，每个风险带缓解措施
  格式：{风险} → {我们的应对} → {对客户的保障}
  诚实展示风险建立信任，但每个风险必须有解

第 10-11 页 — 报价
  第 10 页：报价总览（总价 + 定价模型 + 付款节奏，三项信息一页）
  第 11 页：不包含项摘要（点出最重要的 2-3 条）
  不要在 PPT 上放完整明细表——准备一个附录页或单独 PDF

第 12 页 — 为什么是我们
  选 2-3 个最有说服力的论据：
  - 相关案例（具体项目、效果、可验证）
  - 团队经验（具体谁做过什么）
  - 技术或方法论优势（具体差在哪）
  每条论据必须是客户可以验证的

第 13 页 — 下一步
  明确 Call to Action：
  - 决策时间线（什么时候签约、什么时候启动）
  - 客户需要配合什么
  - 我们的下一步动作
```

#### 每页输出格式

```
页 {N}：《{标题}》({类型：封面/问题/方案/亮点/交付/风险/报价/我们/CTA})

核心信息（这一页唯一想让客户记住的）：
  {一句话}

内容布局：
  - {要点 1}
  - {要点 2}
  - {要点 3}（不超过 4 个要点）
  - 图：{如需图，描述图表类型和内容}

备注（讲稿/设计提示）：
  {这页怎么讲、要不要互动、要不要翻到附录}
```

### C. 讲稿要点

```
讲稿不是念 PPT——PPT 上有的不要全念，PPT 上没有的要铺垫：

第 1 页（封面 — 30 秒）：
  "今天我们来聊 {项目背景}，核心就解决一个问题——{客户痛点}。"
  过渡："为了说清楚我们怎么解决这个问题，先花两分钟看一下现状。"

第 2-3 页（问题 — 2-3 分钟）：
  核心信息 + 一个客户讲过的原话或场景（增加真实感）
  过渡（自然转折）："基于这个情况，我们设计了以下方案——"

第 4-5 页（方案概述 — 3-4 分钟）：
  用一句话把方案说清楚，然后展开架构图
  不要在这里陷入技术细节——技术评估者会在后面的亮点部分认真看
  过渡："这里面有几个设计决策我想展开说一下——"

第 6-7 页（亮点 — 3-5 分钟）：
  每个亮点：问题 → 常规做法的问题 → 我们的做法 → 对客户的好处
  过渡："知道了方案怎么做，我们看看什么时候能看到什么——"

第 8 页（交付 — 1-2 分钟）：
  讲时间线，强调每个阶段客户能看到可验证的东西
  过渡："当然，每个项目都有风险，我想诚实地说一下——"

第 9 页（风险 — 1-2 分钟）：
  "我们识别了 X 个关键风险，这是其中最重要的 3 个，以及我们的应对——"
  每个风险 30 秒
  过渡："好的，那这些要花多少钱——"

第 10-11 页（报价 — 2-3 分钟）：
  先讲定价逻辑（为什么选这个模型），再报数字，再讲付款
  "不包含项我们也列出来了，开诚布公——"
  过渡："最后，我想说一下为什么是我们来做这件事——"

第 12 页（为什么是我们 — 1-2 分钟）：
  2-3 个论据，每个 30 秒
  "总结一下——"

第 13 页（下一步 — 30 秒）：
  明确的 Call to Action
  "如果大家觉得方向 OK，我们建议的下一步是——"

总时长控制：15-25 分钟讲解 + 10-15 分钟 QA
```

### D. Demo 脚本（可选）

```
只在以下情况需要 Demo：
- 已有原型或可演示的 beta 版本
- 方案中有关键交互需要用演示说明
- 客户明确要求看 Demo

Demo 脚本格式：

演示目标：{要证明的 1-2 个核心点}
演示时长：{建议 ≤ 5 分钟}

演示流程：
步骤 1：{场景描述 + 操作} → 展示 {关键点} → {预期客户反应}
步骤 2：...
步骤 3：...

环境准备：
- 需要：{测试数据/账号/网络/硬件}
- 备用方案：{如果现场环境出问题怎么办——录屏/Screenshot/跳过}
- 不要演示：{还不稳定的功能}

演示纪律：
- 不走完整流程，只走关键路径
- 每个步骤先解释"现在我要做 X"，再做，再确认"如大家所见，Y 发生了"
- 如果出错：不掩饰、不慌乱、切备用方案。"这个功能还在优化中，我先用截图说明流程"
```

### E. 客户提问准备

```
预估客户可能问的 5-7 个问题，准备好简短回应：

| # | 可能的问题 | 回应要点 | 需要准备的材料 |
|---|-----------|---------|-------------|
| 1 | "为什么比 XX 公司贵？" | 分解差异点 | 附录：对标分析 |
| 2 | "能不能 2 个月做完？" | 解释关键路径 | 交付节奏里的依赖关系 |
| 3 | "如果需求中途变了怎么办？" | 指向变更机制 | 报价中的变更条款 |
| 4 | "你们做过类似项目吗？" | 指向案例 | "为什么是我们"页的详情 |
| 5 | "技术团队走了怎么办？" | 文档+代码规范+交接流程 | |

回应原则：
- 不回避。"这个问题很好"比"这个我们后面再聊"好得多
- 答不上来的坦诚说——"这个我需要确认后书面答复你"
```

## 输出格式

```markdown
## 展示材料

### 受众分析
{决策者 / 技术评估者 / 使用者，各自的关注点}

### PPT 大纲
{逐页按格式输出}

### 讲稿要点
{逐页核心信息 + 过渡句 + 时长控制}

### Demo 脚本
{如不需要，写"本项目不涉及 Demo"}

### 客户提问准备
| # | 问题 | 回应 | 材料 |
|---|------|------|------|
```

## 常见失败模式

| 表现 | 根本问题 | 正确做法 |
|------|---------|---------|
| PPT 目录 = 方案文档目录 | 没做叙事翻译 | 按"客户理解逻辑"重排，不按文档章节 |
| 架构图直接贴方案文档里的 | 没做视觉简化 | PPT 版架构图 ≤ 5 个框，一眼看懂 |
| "我们有用户模块、订单模块..." | 功能罗列 | 按客户问题和解决路径组织 |
| 报价页放完整明细 | 信息过载 | PPT 只放总览，明细用附录 PDF |
| "为什么是我们" = 一片空话 | 没准备差异化论据 | 每个论据必须是客户可验证的 |
| 讲稿 = 念 PPT 文字 | 没区分书面和口语 | 讲稿是口语，PPT 是视觉辅助 |
| 没准备客户提问就上场 | 以为讲完就结束了 | 提问环节扣分的伤害 ≥ PPT 加分的价值 |

## Rationalization Prevention

| 想说的话 | 真相 |
|---------|------|
| "PPT 就是方案精简一下" | 精简 ≠ 翻译。叙事结构和文档结构完全不同 |
| "客户懂技术，架构图直接贴" | 懂技术的客户更要简化的图——他也会被复杂图消耗注意力 |
| "把所有优势都列上" | 列 10 个优势 = 客户一个都没记住。2-3 个足够 |
| "不写不包含项，等客户问再说" | 没提前说的限制 = 客户默认你包含 = 签了以后扯皮 |
| "问答环节现场发挥就行" | 不准备的问答 = 现场出丑。提前拆弹 |
